Add the shared work queue to Teams

Staff can filter comments and fiscal requests, open response documents, and complete their assigned reviews directly in a channel tab.

Download Teams app package Try the practice workspace

For IT: Download the administrator handoff (ready Teams ZIP plus a separate contact-sync architecture/permission review). Full contact sync requires a protected backend and application permission; it is not enabled by this package.

  1. In the Outlook router, connect SharePoint. Open Work queue → Teams setup → Show Teams connection code. Copy the code. It contains connection IDs and default filters, without sign-in tokens or bill records.
  2. In Teams, open Apps → Manage your apps → Upload an app → Upload a custom app and select the ZIP above. Add Legislative Work Queue to the existing legislative Team. If custom uploads are unavailable, your Teams administrator must make the package available through your organization's app catalog.
  3. In the legislative channel, choose + Add a tab → Legislative Work Queue. Paste the connection code, choose a tab name and optional default session/division, then select Teams' Save button. Repeat only for channels that need a separate tab.
  4. Staff open the tab and choose Load shared work to sign in. They use the same shared requests, documents and history as the router. Each person needs the appropriate SharePoint list access and their assigned role to save review actions.

What staff can filter

Session, division, Comment versus Fiscal data, review/approval stage, approaching or overdue deadlines, missing deadlines, and their own assigned work. Filter selections work together. Requests display their next responsible person and link to the bill conversation and response versions.

Sign-in and permissions

This is a separate Teams tab package; the existing Outlook XML manifest does not change. It uses the existing Entra application and requests only the already-used Sites.ReadWrite.All delegated permission. It does not request mailbox access, Teams messages, new application permissions or a client secret. The Entra registration must already trust brk-multihub://purposebuiltsystems.github.io for nested app authentication. Tenant app policies, consent and users' SharePoint access still apply.

The public deployment uses the commercial Entra registration, including commercial/GCC endpoints. GCC High/DoD need their own sovereign-cloud app registration and hosting configuration, as described in government cloud setup.

The queue reads current shared data when loaded or refreshed. It does not auto-import old conversations or monitor remote file edits; register each revised response before approval. Saving a workflow action does not send Teams messages or email and does not submit to LSA. The practice workspace uses fictional data held only in the page.
