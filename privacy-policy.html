Privacy Policy

Add-in: Legislative Report Router · Publisher: PurposeBuilt Systems LLC · Effective: July 14, 2026

What the app processes

The Outlook router processes report content, public legislative feeds, routing rules and recipient information in the user's browser or Outlook session. The Teams Work Queue processes request details, response links, narrative and fiscal information, assignments, and review/submission history. Microsoft 365 access uses the signed-in user's identity and the permissions approved for the app.

Microsoft 365 data and storage

Shared routing/contact information, tracker data and workflow/audit records are stored in the organization's configured SharePoint lists. Response documents remain in their linked storage locations; the Work Queue registers links rather than uploading the files. Setup choices and saved routing drafts are stored in Outlook add-in settings. Teams tab configuration contains connection identifiers and optional default filters, not access tokens.

The router can read selected Outlook report content and, after the user's confirmation, send division email and post to configured Teams channels. The staff queue requests the delegated SharePoint scope Sites.ReadWrite.All; its workflow actions do not send email, post messages or submit documents to LSA. Existing user access and tenant policies apply.

Hosting and external connections

The app's static interface and public legislative mirrors are hosted on GitHub Pages. Microsoft and jsDelivr content delivery networks supply client libraries. Loading these resources involves ordinary web requests, including network information such as the user's IP address. Public feed sources may also receive requests when a custom URL is used. Manual feed requests omit credentials and referrer information. Do not enter private subscription keys or credentials in feed URLs.

The deployed app does not include analytics trackers or an AI service for report processing. Its application code does not send private report or workflow records to a publisher-operated processing backend. Microsoft 365 operations use Microsoft Graph directly from the client. Hosting, identity and storage providers apply their own service policies.

Review and control

Users control publication and workflow actions. SharePoint permissions control underlying data access; queue filters are organizational views, not separate security boundaries. Organizations manage access, retention and deletion in their Microsoft 365 environment. Practice-mode records stay in the page and disappear when it is reloaded.
